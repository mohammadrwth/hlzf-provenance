# Htrace to W3C PROV

[Htrace](https://github.com/mohammadrwth/htrace) stores a session as typed nodes
(`backend/models/nodes.py`) linked by typed edges (`backend/models/edges.py`), each node tagged
with an actor (HUMAN, LLM, SYSTEM). This repository stores the same kind of graph in PROV-DM
terms. The table shows how one maps onto the other, and where each idea shows up here.

## Actors

| Htrace actor | PROV | Here |
|---|---|---|
| HUMAN | `prov:Person` | reviewer in the UI or CLI (`hlzf:agent/person/<name>`) |
| LLM | `prov:SoftwareAgent` with model id | `hlzf:agent/glm-5.3`, `hlzf:agent/glm-5.3-flash`, `hlzf:agent/glm-ocr` (prompt hash on the activity) |
| SYSTEM | `prov:SoftwareAgent` with version | `hlzf:agent/hlzf-provenance-<version>`, `hlzf:agent/pymupdf-<version>` |

## Node types

| Htrace node | PROV reading | Counterpart here |
|---|---|---|
| SessionStart (input CSV, hash) | Entity generated by an acquisition activity | `hlzf:Document` generated by `hlzf:Acquire` (sha256, URL) |
| Analysis (LLM) | Activity by an LLM agent, generating an Entity | `hlzf:Extract` generating `hlzf:RawExtraction` |
| Suggestion (LLM) | Entity generated by an LLM activity | the raw extraction itself: proposals with page + quote |
| HumanDecision | Activity associated with a Person | `hlzf:Review` (approve / edit / reject) |
| CustomPrompt | Entity used by the next generation (instruction) | review comment (activity attribute) |
| CodeGeneration (LLM, resampled for diagnosis) | Activity by an LLM agent; samples are alternate activities | `hlzf:Extract` with `sample = 1..N`, run by an intervention |
| CodeExecution (sandboxed) | deterministic Activity | `hlzf:Normalize`, `hlzf:Validate` |
| ColumnState (before / after) | Entity versions | `hlzf:Window` revisions |
| ExecutionReview | Activity associated with a Person | `hlzf:Review` |
| SessionEnd | final Entity | query answers and the 15-minute mask, derived from active revisions |

## Edge relations

| Htrace relation | PROV relation |
|---|---|
| analyses, suggests, executes, snapshots | `used` + `wasGeneratedBy` |
| specifies (decision → code generation) | `used` with role |
| decides, reviews | `wasAssociatedWith` a Person + `used` |
| corrects | `wasDerivedFrom` |
| advances_version | `wasRevisionOf` (PROV-JSON: `wasDerivedFrom` with `prov:type = prov:Revision`) |
| alternative_to (attempts) | sibling activities with different `sample` attributes |
| contains (container nodes) | not needed; PROV bundles would be the equivalent |

## Fault localisation

| Htrace | Here |
|---|---|
| symptom predicate, confirmed by the user | issue raised by a deterministic check (grounding, cross-check, coverage) |
| locate: first false → true flip on the version chain | the stage chain is fixed (acquire → parse → extract → normalize), so locating means choosing between them |
| discriminate: resample the implementation N = 10 times under the same intent | resample the extraction N = 5 times on the same parsed pages |
| p̂ ≥ 0.6 → instruction fault (the intent entails the symptom) | p̂ ≥ 0.6 → upstream of extract (the input entails it) |
| p̂ ≤ 0.4 → implementation fault | p̂ ≤ 0.4 → extract fault |
| Wilson 95 % interval, quorum of evaluable samples caps confidence | same |
| repair: a passing resample is a verified patch | consensus correction (`hlzf:AutoCorrect`): when OCR and vision agree and every value is printed in the cell, the cell is set to that reading, a revision with the software as agent; otherwise the reading is a suggestion |
| (no second stage) | do(parse := GLM-OCR) separates a lying text layer (parse) from a document that prints the error (source_document) |
